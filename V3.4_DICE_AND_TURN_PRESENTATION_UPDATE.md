# V3.4 Dice and turn-presentation update

This patch is based on live host-screen testing. It does not change the agreed Ludo rules.

## Dice presentation

The previous CSS cube could rotate fully edge-on to the camera, producing a thin bright sliver and sometimes an apparently empty dice tray. V3.4 replaces that presentation with a stable perspective die that always retains a readable surface.

Roll sequence:

1. The server enters `rolling` and locks input.
2. The host shows `ROLLING – Dice in motion…`.
3. The die hops, tilts and rotates without turning edge-on. Intermediate faces change during the tumble.
4. The server-generated face is revealed.
5. The host holds `RESULT – X` clearly.
6. Movement begins only after the server's rolling lock expires.
7. The final face stays visible until the next roll.

Opening-boost bonus rolls use the same presentation and are labelled `BONUS ROLL`.

## Visible between-turn gap

The existing server phases remain authoritative, but they are now made obvious on the TV.

During `resolving`, the host shows a dedicated **MOVE RESOLVING** card and a progress bar. During `turn_gap`, it changes to **NEXT TURN** or **EXTRA TURN**, identifies the player who will act next, and continues the progress bar until controls unlock.

No phone can roll or select a token while these phases are active.

## Pacing

Standard speed is intentionally calmer than V3.3. The main changes are 250 ms per normal token hop, a 320 ms base resolve allowance, and a 1.25 second between-turn pause. The other speed profiles remain available.
